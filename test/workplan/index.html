学习计划 v4 · 六个月全天候

长期目标：Java 架构师 / AI 全栈
周期：2026-10-11 → 2027-04-10（26 周 · 每天 6 小时 · 约 1100 小时）
起点：2026-10-11（周日，启动日，同时也是每周的减半日）
Java 专项见：test/javaplan.md

上篇 · 能力地图（长期）

0. 四个阶段，真正在考什么

阶段 表面看是 本质核心能力 自测标准
小白 会写代码 建立因果直觉：知道每行代码为什么这么写，能独立调试报错 独立把一个小需求从 0 跑到通
企业入职（初级） 能干活、能交付 在约束下可预测地交付：命名规范、Git/CR、日志与异常、单测、进度同步 别人能无痛接手你的代码
中级 能解决难题 把不确定问题收敛成确定解：性能、并发、线上排障、模块设计、技术方案 线上故障由你定位到根因
高级 / 架构 能画图定方案 权衡与抽象：信息不全、多目标冲突下做取舍，划边界、定演进、控复杂度与成本 你的方案别人能执行，且一年后还站得住

一句话：小白练理解 → 初级练交付 → 中级练收敛 → 高级练取舍。

1. 能力骨架（越往后，越靠下面几项）

  • 语言与运行时：Python / Java 基础、集合源码、JMM、类加载、GC
  • 并发与异步：线程池、锁、异步编排
  • 框架：FastAPI / Spring（IoC、AOP、自动装配）
  • 数据：SQL、MySQL（索引 / 执行计划 / MVCC / 锁）、Redis
  • 中间件：MQ（幂等 / 顺序 / 事务消息）、分布式锁
  • 分布式：CAP、一致性、限流熔断降级、链路追踪
  • AI 应用：LLM API、Prompt、RAG、向量库、Agent / MCP
  • 架构：DDD、分层与边界、微服务拆分、容量估算
  • 工程化：Git、CI/CD、Docker/K8s、可观测性、压测
  • 软能力：技术方案文档、ADR、跨团队推动

下篇 · 26 周路线

2. 6 小时怎么分（整套计划最重要的设计）

6 小时不是连续学 6 小时，而是四种性质不同的活动各占一块。

时段 时长 内容 硬性产出
上午 2h 刻意练习：算法 1 题（30 min）+ 当周主题动手写（90 min） 1 道题 + 1 段能跑的代码
下午 2.5h 项目推进：真实项目，写代码为主 1 个 commit + 能演示的产物
傍晚 1h 限时输入：官方文档 / 源码 / 课程 3 条笔记
晚上 0.5h 输出与规划：当日笔记 + 明日任务 笔记 + 明日 3 件事

三条纪律

  1. 6 小时里至少 4.5 小时在动手，限时输入不超过 1.5 小时。这条比什么都重要。
  2. 每 50 分钟休息 10 分钟，不要硬撑。
  3. 每天必须留下 commit。没有 commit 的一天 = 没学。

3. 项目主线：一个项目贯穿 26 周

不要做十几个小项目。只做一个，让它逐周长大——这样你能看见系统是怎么长出来的，而不是每次从零开始。

项目：AI 内容助手 —— 抓取技术热点 → LLM 生成中文摘要 → 发布 / 提供服务 → 最后变成能查你笔记的问答服务。

阶段 形态
W2–W6 命令行脚本 → 每天自动产出 Markdown 内容
W7–W12 Web 服务 → 有界面、有数据库、有用户、公网可访问
W13–W18 Java 重写后端 → 前后端分离 + 缓存
W19–W22 接入 RAG / Agent → 能查你自己的 Obsidian 笔记
W23–W26 架构收口 → 技术方案文档 + 简历 + 面试准备

4. 每周节奏与防崩盘机制

  • 周一～周六：满负荷 6 小时
  • 周日：减半（3 小时），下午完全断网休息
  • 法定节假日当周自动减半，不要为了「进度」硬补
  • 每晚睡前 5 分钟：写明天的 3 件事

每 6 周一次体检（W6 / W12 / W18 / W24 的周日做），回答 5 个问题：

  1. 这 6 周我一共提交了多少次 commit？
  2. 有没有一个能演示给别人看的东西？
  3. 有没有真人用过我做的东西？
  4. 我能不能不看资料，把这 6 周学的东西讲清楚？
  5. 我的睡眠和情绪还正常吗？

任何一条答不上来 → 下一周减半，把它补上，别硬冲。六个月是马拉松，中途放弃是最大的失败方式，比学得慢严重得多。

8. 六个月里最大的六个坑

  1. 前松后紧。 26 周听起来很长，前两个月最容易松懈。用每 6 周的体检卡住。
  2. 6 小时全在输入。 看视频 6 小时，一周后什么都不会。输入硬性上限 1.5 小时。
  3. 中途换方向。 听说前端好、听说算法重要，就换赛道。一条线走完再换。
  4. 不出门、不见人。 每周至少找一个真人聊一次你的代码或项目。
  5. 追求完美方案。 先跑通再优化——一个能跑的丑东西，胜过一个不能跑的美方案。
  6. 一遇报错就换方案。 报错的最后一行才是你真正的老师，先读懂它。
